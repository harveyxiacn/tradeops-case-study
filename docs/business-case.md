# 案例一 贸易询盘与报价审批

**状态：为作品集生成的模拟案例。** 虚构公司 Harbour Trade Demo，所有客户、金额、对话和流程规则均为合成材料。题材参考你熟悉的贸易协调工作，不代表 Bright Maple 或 Polar 已使用此系统。

## 业务问题与访谈示例

假设一个 5 人贸易团队用邮件、聊天和 Excel 跟进报价。销售关心能否及时回复，经理关心低毛利和信用条款，运营关心资料是否完整。不能直接假设他们愿意买 AI；先确认重复录入和审批延迟是否真正造成问题。

| 模拟问题 | 模拟回答 | 转化为需求 |
|---|---|---|
| 什么情况最常需要回头补资料？ | 产品规格、交货地点和币种缺失 | 提交前校验，并允许草稿暂缺字段 |
| 谁能批准折扣？ | 经理；销售不能批准自己的报价 | 服务端权限与审批人分离 |
| 改价后旧审批是否有效？ | 无效，需要重新批准 | 报价版本快照与重新提交 |
| 什么时候算逾期？ | 提交后超过 48 个连续小时未决定 | 保存 submitted_at；报表按固定口径计算 |
| 最重要的成功指标是什么？ | 完整资料的比例和查找状态的时间 | 数据完整率与受控任务耗时；暂不承诺营收提升 |

真实访谈时要重新问这些问题，记录参与者同意与实际答案。不能把本表标成客户调研结果。

## As Is 与 To Be

As Is：收到询盘 → 人工抄字段 → 查价格 → Excel 报价 → 发消息求审批 → 查聊天找决定 → 手动记录跟进。假设风险是版本不一致、信息遗漏、责任不清。

To Be：录入询盘 → 必填校验 → 生成报价版本 → 服务端计算金额及毛利 → 指定经理审批 → 批准／驳回留痕 → 导出带版本号的报价草稿。MVP 不自动给客户发邮件，不连接真实采购、支付或物流服务。

## 业务规则与已算好的示例

演示只支持 HKD、USD，两位小数，单位为整数件；HKD 汇率固定为 1，USD 到 HKD 使用合成快照 7.80，不是实时汇率或报价建议。暂不建模税、关税、运费与复杂 Incoterms 成本；运费仅为备注，不计入毛利。

输入：100 件 SKU-DEMO-A，单价 USD 20.00，单件成本 USD 14.00，折扣 5%。行总额 2,000.00；折扣 100.00；净额 1,900.00；成本 1,400.00；毛利 500.00；毛利率 26.3158%；HKD 净额 14,820.00。

净额超过 HKD 10,000，或毛利率低于 20%，或付款期超过 30 天时，标记 additional_review。所有报价仍需他人审批；标记只影响审核提示，不意味着低于门槛可自动外发。恰好 HKD 10,000 不触发金额条件，恰好 20% 不触发毛利条件。

另一个例子：100 件 × HKD 100，成本每件 HKD 85，无折扣，净额 10,000，毛利率 15%，应因低毛利标记，不是因金额。

## 用户故事与验收

US01：作为销售，我希望先保存不完整询盘，以便稍后补充。验收：草稿可缺交货地点；提交报价时缺少该字段应返回字段级错误，数据库没有 Pending 状态的新版本。

US02：作为经理，我希望看到提交时的不可变版本。验收：销售提交 v1 后调整价格，只能创建 v2；v1 的价格、审批与审计记录不变，v1 不得再次导出为当前有效报价。

US03：作为运营，我希望知道哪些审批逾期。验收：在固定测试时钟下，Pending 超过 48 小时计入逾期；已批准、已驳回和正好 48 小时不计入。

## 方案取舍

Excel 改善版成本最低、适合确认规则，但多人修改与审批审计仍需约定。Power Platform 适合已有 Microsoft 环境的内部流程，需核实租户、权限和许可。定制 Web app 能展示 API、SQL 和测试，但开发与维护责任更多。作品集选择定制最小版，并用小型 Power Platform 实验展示工具能力；不宣称任一种对所有公司都最优。

## 价值模型而非已实现 ROI

假设每月 80 条询盘，每条整理耗时从 12 分钟到 7 分钟，理论节省 400 分钟，即 6.67 小时。若人工成本假设 HKD 150／小时，则毛节省约 HKD 1,000／月；尚未扣软件、维护、培训、复核及错误成本。实际比较应使用相同任务、相同完整度标准、多次重复测量，报告样本数与限制。不能在简历写“为公司节省 42% 时间”。
